# Data contracts

_Payload tables are generated by `scripts/generate_docs.py` from `schemas/contracts.py`, the single source of truth that also produces the Avro (`schemas/avro`) and JSON Schema (`schemas/json`) files._

## Contract rules

| Rule | Enforcement |
|---|---|
| Every event uses the standard envelope | Avro record `<Entity>Event`; producers validate with fastavro before sending |
| Schemas are registered per topic (`<topic>-value`, TopicNameStrategy) | `ingestion.kafka_producers.admin bootstrap`; producers run with `auto.register.schemas=false` |
| Compatibility mode **BACKWARD** | Schema Registry rejects breaking changes; CI `check-compat` gate |
| Allowed change: add an optional field with a default; widen int→long | Consumers decode old and new events (writer→reader schema resolution in Bronze) |
| Breaking change (remove / rename / retype a required field) | New topic version (`ecommerce.orders.v2`), dual-publish during migration |
| Timestamps are UTC, `timestamp-millis` | Contract type |
| Monetary amounts are decimals in the order currency, rounded to minor units | Producer + Silver `total_reconciles` check |
| PII (names, e-mail) only in `customers` events | Masked/hashed in Silver; Bronze access restricted |
| Invalid events go to `ecommerce.dead-letter` with the error | Producer validation + Bronze decode |

## Envelope

| Field | Type | Description |
|---|---|---|
| `event_id` | string | Globally unique event id (UUID); dedup key |
| `event_type` | string | Business event name (allowed values per topic below) |
| `event_version` | int | Payload contract version |
| `event_timestamp` | timestamp-millis | Business event time (UTC) |
| `source_system` | string | Emitting system |
| `correlation_id` | string | Ties all events of a journey / order together |
| `payload` | record | Entity payload (below) |

## `ecommerce.customers` (customers)

Customer lifecycle events (registration, profile / loyalty changes).  
Key: `customer_id` · Partitions: 3 local / 6 full scale · Retention: 14 days  
Event types: `customer_registered`, `customer_profile_updated`

| Field | Type | Required | Description |
|---|---|---|---|
| `customer_id` | string | yes | Business key, CUST-nnnnnnn |
| `first_name` | string | yes | PII - masked in Silver |
| `last_name` | string | yes | PII - masked in Silver |
| `email` | string | yes | PII - hashed/masked in Silver |
| `country` | string | yes | ISO 3166-1 alpha-2 |
| `registration_date` | timestamp | yes | UTC |
| `customer_segment` | string | yes | consumer | small_business | corporate |
| `loyalty_status` | string | yes | none | bronze | silver | gold | platinum |
| `marketing_opt_in` | boolean | yes | GDPR marketing consent |
| `updated_at` | timestamp | yes | Last change in the source system (UTC) |

## `ecommerce.orders` (orders)

Order header lifecycle; keyed by order_id so status transitions stay ordered.  
Key: `order_id` · Partitions: 6 local / 12 full scale · Retention: 7 days  
Event types: `order_created`, `order_confirmed`, `order_cancelled`, `order_shipped`, `order_delivered`, `order_returned`

| Field | Type | Required | Description |
|---|---|---|---|
| `order_id` | string | yes | Business key |
| `customer_id` | string | yes | FK customers |
| `order_timestamp` | timestamp | yes | Order placement time (UTC) |
| `order_status` | string | yes | created | confirmed | cancelled | shipped | delivered | returned |
| `status_reason` | string | no | Reason for cancellation |
| `sales_channel` | string | yes | web | mobile_app | marketplace | social_commerce |
| `currency` | string | yes | ISO 4217 |
| `subtotal_amount` | double | yes | Sum of quantity * unit_price |
| `discount_amount` | double | yes | Promotion discount |
| `shipping_amount` | double | yes | Shipping fee |
| `tax_amount` | double | yes | VAT / sales tax |
| `total_amount` | double | yes | subtotal - discount + shipping + tax |
| `promotion_id` | string | no | Applied promotion |
| `country` | string | yes | Ship-to country |
| `session_id` | string | no | Web/app session that produced the order |
| `item_count` | int | yes | Units in the order |
